# Faz 5 AI Entegrasyonu Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Gunluk kayitlarini OpenAI uyumlu bir provider ile background'da iyilestirmek, onerileri saklamak ve sahiplik kontrollu accept/reject akisini tamamlamak.

**Architecture:** Saf provider/parser katmani AI cevabini dogrular. Sinirli `ThreadPoolExecutor` yalniz log ID'leriyle calisir; servis atomik `PENDING -> PROCESSING` claim'i yapar. Startup recovery eski `PENDING` ve stale `PROCESSING` kayitlari tekrar kuyruga alir.

**Tech Stack:** Python 3.12, Flask 3.1, Flask-SQLAlchemy 3.1, Alembic/Flask-Migrate, OpenAI Python SDK, pytest.

## Global Constraints

- Tasarim kaynagi: `docs/superpowers/specs/2026-09-14-faz5-ai-design.md`.
- `raw_content` hicbir AI veya karar akisinda degistirilmez.
- Thread'e yalniz `log_id` verilir; ORM nesnesi ve request session'i verilmez.
- Provider cevabi exact JSON schema parser'dan gecmeden saklanmaz.
- Topic yalniz ayni kullanicinin mevcut root topic'iyle normalize ad uzerinden eslesir; yeni topic olusturulmaz.
- `refined_content` en fazla 50000 karakter, her oneri listesi en fazla 25 oge, her ad 1-100 karakterdir.
- Testing config AI ve recovery'yi varsayilan kapatir; testlerde gercek ag cagrisi yapilmaz.
- SQLite migration kaniti PostgreSQL enum kaniti sayilmaz.

```python
class AIProviderInterface(ABC):
    @abstractmethod
    def refine(self, raw_content: str) -> str:
        raise NotImplementedError

class OpenAIProvider(AIProviderInterface):
    def __init__(self, *, api_key: str, base_url: str, model: str,
                 timeout_seconds: float, client=None):
        self.client = client or OpenAI(api_key=api_key, base_url=base_url,
                                      timeout=timeout_seconds)
        self.model = model
    def refine(self, raw_content: str) -> str:
        response = self.client.chat.completions.create(
            model=self.model,
            messages=[{"role": "system", "content": SYSTEM_PROMPT},
                      {"role": "user", "content": raw_content}],
            response_format={"type": "json_object"},
        )
        return response.choices[0].message.content
```

Pin the selected OpenAI 1.x SDK in `requirements.txt`. Send the fixed guardrail prompt and `response_format={"type": "json_object"}`. Translate SDK failures to sanitized `AIProviderError`.

```python
@dataclass(frozen=True)
class AIResult:
    refined_content: str
    technologies: tuple[str, ...]
    topics: tuple[str, ...]
    tags: tuple[str, ...]

class AIOutputError(ValueError):
    pass

def parse_ai_output(payload: str) -> AIResult:
    data = json.loads(payload)
    if not isinstance(data, dict) or set(data) != EXPECTED_KEYS:
        raise AIOutputError("AI output must match the required JSON schema")
    return AIResult(
        refined_content=_validate_content(data["refined_content"]),
        technologies=_validate_names(data["technologies"], "technologies"),
        topics=_validate_names(data["topics"], "topics"),
        tags=_validate_names(data["tags"], "tags"),
    )
```

Use `json.loads`; require exact keys and reject rather than coerce invalid values. Detect duplicate names after the existing `normalize_name` helper.

- [ ] **Step 4: Implement worker and executor**

Claim with one conditional SQL update:

```python
updated = db.session.execute(
    db.update(DailyLog)
    .where(DailyLog.id == log_id, DailyLog.ai_status == AIStatus.PENDING)
    .values(ai_status=AIStatus.PROCESSING, ai_processing_started_at=utcnow())
).rowcount
```

Commit the claim before the provider call. Open `app.app_context()` inside the worker; on success save parsed values and clear processing time. On provider/parser failure rollback active work, reload the claimed row, set `ERROR`, clear processing time, commit, and log only exception type plus log ID. Always call `db.session.remove()`.

Recovery first resets stale `PROCESSING` records to `PENDING`, commits, then queries only the configured batch of `PENDING` IDs and calls `executor.submit(id)`. `AIExecutor` owns a `ThreadPoolExecutor(max_workers=...)` and binds app/provider without exposing ORM objects.

```python
def start_ai_recovery(app: Flask) -> int:
    if not app.config["AI_ENABLED"] or not app.config["AI_RECOVERY_ENABLED"]:
        return 0
    return AIService.recover_pending(
        app, app.extensions["ai_executor"],
        batch_size=app.config["AI_RECOVERY_BATCH_SIZE"],
        stale_after_seconds=app.config["AI_STALE_AFTER_SECONDS"],
```
